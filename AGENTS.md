# AGENTS

## Project

Terraform provider `agora-calyce/spx` for Superphenix (SPX), built with the Terraform Plugin Framework (protocol v6). It does **not** call the SPX API directly: it talks to the SPX TF Proxy API ([`spx-tf-api`](https://github.com/Agora-Calyce/spx-tf-api)), which exposes flat, synchronous resources with Terraform semantics. The provider stays thin and only maps Terraform attributes to the proxy's JSON.

Any SPX-specific behaviour (polling, field normalization, filtering of system data, 404 handling) belongs in the proxy, not here. See `https://github.com/Agora-Calyce/spx-tf-api/blob/main/README.md` ("Workarounds", and "Workarounds in the provider" for the few exceptions that depend on Terraform state/plan).

## Commands

```bash
make build      # go build + copy binary to ~/.terraform.d/plugins/registry.terraform.io/agora-calyce/spx/1.0.0/<os>_<arch>
make test       # go test -v ./...  (unit tests only; acceptance tests are skipped without TF_ACC)
go test ./internal/provider -run TestInstanceResource_ModelMatchesSchema
TF_ACC=1 go test ./internal/provider -run TestAccVPCResource   # needs a running proxy + SPX credentials
make docs       # regenerates docs/ with ~/go/bin/tfplugindocs
```

Provider config: `endpoint` (proxy URL, default `http://localhost:8080`), `api_token`, `az`, `orga_id`, `project_id`, or env vars `SPX_API_ENDPOINT`, `SPX_API_TOKEN`, `SPX_AZ`, `SPX_ORGA_ID`, `SPX_PROJECT_ID`.

To try changes end to end: run the proxy locally (`make run` in `spx-tf-api`), `make build` here, then `terraform init && terraform apply` in an `examples/projects/<resource>/` directory.

## Layout

- `main.go`: provider server, address `registry.terraform.io/agora-calyce/spx`.
- `internal/provider/provider.go`: provider schema/configuration and the list of resources and data sources.
- `internal/provider/<name>_resource.go`: one file per resource (`spx_vpc`, `spx_vpc_static_routes`, `spx_subnet`, `spx_disk`, `spx_eip`, `spx_load_balancer`, `spx_ssh_key`, `spx_instance`, `spx_security_group`). `instance_helpers.go` holds the instance model ↔ client conversions.
- `internal/provider/*_data_source.go`: `spx_storage_classes`, `spx_vm_types`.
- `internal/client/client.go`: HTTP client for the proxy (request/response structs + CRUD methods per resource, 10 min HTTP timeout so it outlasts proxy polling).
- `internal/provider/*_test.go`: unit tests plus `TestAcc*` acceptance tests. `upstream_fields_test.go` checks that every model struct matches its real schema (`setModel`), so a missing `tfsdk` field fails the build.
- `docs/`: generated by tfplugindocs. Do not edit by hand, run `make docs`.
- `examples/projects/`: one runnable directory per resource, plus `full/` (VM + EIP + LB + security group). `examples/provider/provider.tf`, `examples/resources/<type>/resource.tf` and `examples/data-sources/<type>/data-source.tf` are the snippets `make docs` puts in the "Example Usage" section of each Registry page.

## Conventions

- Schema rules mirror the proxy/SPX behaviour:
  - fields SPX cannot update → `RequiresReplace` (e.g. SSH key `public_key`, disk `storage_class`/source, subnet CIDRs/VPC);
  - computed fields filled only after reconciliation → `UseStateForUnknown`, to avoid `(known after apply)` noise;
  - `cloud_init` on instances is only read back when set in config, and keeps state values when the proxy returns them empty.
- Every write method reads the resource back from the proxy response and writes the full state; never leave a computed attribute unknown after apply.
- Code comments, README and generated docs in English. Follow the style of the file you edit.

## Adding or changing a field / resource

1. Proxy first (`spx-tf-api`): model, handler mapping, tests.
2. Here: struct in `internal/client/client.go` (+ client method if new resource), schema + model + CRUD in the resource file, register new resources in `provider.go`.
3. Update `upstream_fields_test.go` / resource tests so the model matches the schema.
4. Add or update the example in `examples/projects/<resource>/` and the doc snippet in `examples/resources/<type>/resource.tf`, then run `make docs`.

## Gotchas

- `README.md` is incomplete (the "Examples" section is cut off).
- `main.version` defaults to `dev` and is injected with `-ldflags`: `VERSION` in the `Makefile` for local builds (also used for the local plugin path), the git tag for releases. Releases are built, GPG-signed and published to GitHub Releases by GoReleaser (`.goreleaser.yml`, `.github/workflows/release.yml`) on `v*` tags, in the layout the Terraform Registry expects.
- `.terraform/`, `*.tfstate`, `terraform.tfvars` and the `terraform-provider-spx` binary are gitignored; never commit credentials from the tfvars files.
